# Build Harness

把目标仓库整理成：任何 agent 进入后，**只读仓库自身的文件**就知道开工前读什么、事实写在哪、决策记在哪、改完要同步什么、运行哪条命令验证。这个 skill 负责一次性的调查、设计与搭建；后续日常维护依靠搭好的仓库规则和检查命令完成，不依赖再次调用本 skill。因此，凡是后续 agent 需要遵守的维护规则，都必须落进目标仓库。

## 核心模型

三层信息，各有唯一归属（one home per fact），其他位置只链接：

| 层 | 内容 | 不放 |
| --- | --- | --- |
| 根 / 子树 `AGENTS.md` | 每次会话都需要的常驻规则，每条一到三行，并链接到详细出处；子树文件只放该目录特有的规则 | 故事、示例、情景化流程、从链接处复述的内容 |
| `docs/` | 当前系统事实：架构、模块契约、开发流程、how-to | 历史演变、决策理由、实现状态标注（“已完成！”“未来会……”） |
| 决策记录 | 持久的决策依据：问题、决定、放弃了什么、后果 | 机械性或局部修改、迁移任务清单 |

几条容易做错的决策：

- **新建的 Agent Notes 中，已实施记录要保持事实最新**：代码移动文件、重命名、改默认值时，在同一改动中更新记录里的路径、名称等事实；只有决策本身被推翻才新建记录取代；只有归档记录冻结不改。沿用的 ADR 若规定采纳后不可修改，服从原约定，事实变化通过新记录或其规定的方式反映。
- **长度预算只约束少数常驻文档**（如根 `AGENTS.md`、`docs/AGENTS.md`），不对所有文档统一限长；超限时优先迁移到正确的层，其次压缩，最后才在说明理由后提高上限。
- **脚本只检查可机械判断的规则**；内容真实性、架构解释和决策依据由 agent 对照代码与证据审核。
- **沿用成熟的既有约定**：仓库已有运作良好的 ADR、文档目录或检查工具时，在其上补齐规则，不强行迁移到新布局，也不套用与之冲突的检查。

规模按目标仓库裁剪。小仓库可能只需要根 `AGENTS.md`、一个 `docs/AGENTS.md` 和少量决策记录。目录在第一次有内容时再建，不制造空目录、空分类或无人维护的模板。

## 流程

1. **调查目标仓库。** 阅读已有的 `AGENTS.md` / `CLAUDE.md`、README、`docs/`、ADR / RFC / 设计文档、脚本、包管理与构建命令、CI 配置和 git 历史。识别可沿用的机制（已有 ADR 目录、链接检查、CI 工作流）、真实的模块划分和团队语言习惯。命令和事实必须核实（运行或对照代码），不从记忆或类似项目推断。
2. **设计方案。** 读 [references/layering.md](references/layering.md) 与 [references/agent-notes.md](references/agent-notes.md)，确定：哪些目录值得拥有子树 `AGENTS.md`；docs 的分层与每类事实的归属；决策记录是新建 Agent Notes 还是沿用已有 ADR；现有内容如何迁移（重复规则合并、历史叙述移入决策记录或删除、决策理由从 README 抽出）。
3. **与用户确认方案与自动化程度。** 这是对目标仓库的多文件改动，遵守目标仓库与当前会话的审批规则。说明计划新建 / 移动 / 改写的文件，然后让用户选择自动化程度，并结合这个仓库说明每档的具体收益和新增文件：
   - **仅文档体系**：分层 `AGENTS.md`、docs、决策记录及其维护规则。
   - **文档体系 + 本地检查脚本**：额外加入可运行的检查命令，并写进 `AGENTS.md` 的完成前检查。
   - **文档体系 + 检查脚本 + CI**：额外在推送 / PR 时自动运行同一命令。

   用户已明确指定范围或档位时直接采用，不重复询问。确定后全程保持：不超出所选档位增加脚本、钩子或 CI，也不缩减用户要求的内容；需要调整时先问用户。
4. **实施。** 先搭文档体系并写入维护规则（见 layering.md 的“必须写入目标仓库的维护规则”）。选择了脚本时读 [references/checks.md](references/checks.md)；选择了 CI 时再读 [references/ci.md](references/ci.md)。
5. **验证。** 复查每条链接和命令都真实可用；对照代码抽查 docs 中的事实陈述；确认根 `AGENTS.md` 没有复述下游文档的内容。有检查脚本时，既要让当前仓库通过，也要在隔离的临时副本中用错误样例证明每项检查确实会失败（见 checks.md）。

## 交付

向用户报告：所选范围与自动化档位；新建与改动的文件；各层归属规则落在哪个文件；实际运行过的检查命令和结果；未能核实或刻意留空的部分（例如需要人工确认的历史决策理由）。不要声称运行过没有运行的命令。
