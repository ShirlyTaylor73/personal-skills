# 分层 AGENTS.md 与 docs

## 根 AGENTS.md

开头用一两句话说明项目是什么，并链接进入代码前必读的文档（通常是 `docs/architecture.md`）和文档规范（`docs/AGENTS.md`）。之后按需包含：

- **仓库布局**：一级目录及一行职责；有子树 `AGENTS.md` 的目录标出来。
- **命令**：安装、构建、测试、lint、文档检查等，每条一行注释。只列真实存在且运行过的命令；说明哪些需要密钥或网络。
- **验证原则**：改动对应的最小检查是什么，何时才跑全量，CI 负责什么。
- **约定**：每条一到三行的常驻规则，粗体规则名加链接到出处（docs 或 note）。规则来自代码、review 历史或用户确认，不凭空编造“最佳实践”。
- **文档与 notes 规则摘要**：见下文“必须写入目标仓库的维护规则”。
- **编辑本文件的规则**：保持每条规则独立、只链接不复述；有预算检查时说明超限的处理顺序。

如果多个 agent 客户端读取不同文件名（如 Claude Code 读 `CLAUDE.md`），让 `CLAUDE.md` 作为指向 `AGENTS.md` 的符号链接或一行引用，只维护一份真实内容；先确认目标平台和用户是否接受符号链接（Windows 检出可能有问题）。

## 子树 AGENTS.md

只在目录有**该目录特有**且 agent 在其中工作时必须知道的规则时才创建，例如：`packages/`（包导出形式、测试位置）、`docs/`（文档规范）、`scripts/`（脚本编写约束）、notes 目录（生命周期规则）、`vendor/`（禁止直接修改）。开头一句说明它补充哪个上级文件，不重复上级已有的规则。没有特有规则的目录不建。

## docs 分层

在 `docs/AGENTS.md` 中写一张“层—职责—不放什么”的表，作为整个仓库的放置规则。按目标仓库实际需要选择层，常见的有：

| 层 | 职责 |
| --- | --- |
| `architecture.md` | 有序的系统地图：组成、核心模块、主流程、扩展点；改核心代码前必读 |
| 模块 / 包 README | 该模块的契约：配置、语义、限制、扩展点 |
| 子系统参考页 | 类型定义与语义 |
| `cookbook/` | 带验证步骤的分步 how-to |
| `development.md` | 开发环境、日常流程、CI 概要 |
| `postmortem/` | 事故复盘，唯一允许叙事的层 |
| 生成的参考 | 从源码生成的目录 / 表格，禁止手改 |

放置速查（写进 `docs/AGENTS.md`）：缺陷经历 → postmortem；决策理由 → Agent Notes；操作流程 → cookbook；模块契约 → 模块 README；常驻规则 → 根 `AGENTS.md` 并链接理由。

写作规则中最关键、也最需要写进目标仓库的几条：

- **只写当前状态。** 历史留在 commit、PR、notes、postmortem 中；文档描述现存机制，不描述“改成了什么”。
- **每个事实只有一个归属。** 发现重复时搜索特征短语，保留一处，其余改为链接。
- **按树的位置限定范围。** 文档详细描述自身主题，对子级只描述职责，细节链接到子级。
- **不手写会漂移的清单。** 源码或生成器是权威时，链接或生成，不手工复述。
- 可在 `docs/AGENTS.md` 附一份“问题清单”（重复规则、实现状态标注、推理过程式叙述、段落墙、强调泛滥），供 agent 审查时逐项对照。

## 迁移已有内容

- 已有 ADR / RFC / 设计文档：优先迁入 notes 体系并按生命周期归类；如果团队已有成熟的 ADR 目录和格式，沿用并在规则中说明，而不是强行改名。
- README 或 wiki 中的决策理由：抽到对应 note，原处留一行链接。
- 过时内容：对照代码修正；无法核实的事实不要保留为当前事实，列入交付报告由用户决定。
- 移动文件后修复所有入站链接。

## 必须写入目标仓库的维护规则

这些规则是后续 agent 无需本 skill 也能维护仓库的关键，按归属分别写入：

- **根 `AGENTS.md`**：开工前读哪些文档；文档随代码改动在同一提交中更新；何时需要写或更新 Agent Note（链接到 notes 规则）；完成前运行哪条检查命令（有脚本时）。
- **`docs/AGENTS.md`**：分层表与放置速查、写作规则、预算处理顺序（有预算检查时）。
- **notes 目录的 `AGENTS.md` / README**：创建条件、格式、生命周期迁移、取代检查、归档与冻结规则（见 [agent-notes.md](agent-notes.md)）。
- **检查脚本与 CI**：执行其中可机械判断的部分；规则文字中注明对应的检查命令，方便 agent 在失败时找到规则出处。
