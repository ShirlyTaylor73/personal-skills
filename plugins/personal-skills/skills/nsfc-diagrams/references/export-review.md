# SVG导出与验收

## 可编辑与便携

默认交付标准 SVG 和同名 PPTX 可编辑副本，不生成 `.drawio` 文件，也不在 SVG 中内嵌 draw.io 模型。不要输出无法恢复结构的位图伪 SVG。

SVG中：

- 场景照片通过data URI内嵌，不依赖本机绝对路径或临时URL。
- 标签使用真正的SVG文字；图标、线条和箭头保持矢量，保留可编辑来源。
- 不以foreignObject承载核心标签，减少Word和其他软件的显示差异。
- viewBox、宽高与实际画面边界对应；照片保持比例，四周有一致余量。
- 写入内容说明或无障碍描述即可，不在图面加入程序实现细节。

## SVG导入PPTX

采用 presentations 技能，将最终 SVG 作为 SVG 资源嵌入 PPTX，不能用整图 PNG 或截图替代。默认一图一页，白底，页面比例匹配 SVG，保持原有布局、字体和颜色，不另加封面、标题或装饰。嵌入照片继续作为图像，其他元素保留矢量。

导入的 SVG 图形通常可以整体移动和缩放，但这不代表文字、箭头等已成为可分别编辑的 PowerPoint 对象。需要逐元素编辑时，在支持的 PowerPoint 版本中使用“转换为形状”并按需取消组合，检查标签、箭头和照片是否能够单独选择。标签若转成轮廓，只能编辑形状，不能宣称可修改文字内容；确需修改文字时，恢复对应的原生文本框并核对位置和字体。

无法执行或核验转换时，保留 SVG 导入版并明确其编辑范围，不能宣称已完成逐元素编辑，也不能擅自改用 draw.io。保留独立 SVG，便于后续修改和重新导入。

按 presentations 技能的流程渲染 PPTX，检查与 SVG 的视觉一致性，并确认文档资源中实际保留 SVG。仅确认 PPTX 能打开或只保留位图预览不足以通过验收。

## 字体与兼容

确保所用中文字体在渲染环境存在；检查中文、英文、数字和符号。SVG保留字体名并在交付时说明实际需要的字体，仅在可合理分发时嵌入字体。

Word等软件对SVG基线属性可能处理不同。不要只依赖dominant-baseline完成垂直对齐；根据字体明确设置基线并在目标软件渲染核对。文字转轮廓只能作为用户需要跨平台固定外观的兼容副本，不能悄悄取消主源文件的文字编辑能力。

图标与箭头head须留在局部viewBox内；检查嵌套SVG边界，避免末端被切掉。marker的大小须与线宽匹配，不能因缩放出现巨大箭头或几乎不可见的箭头。

## 渲染检查

先用实际SVG渲染器打开或导出PNG，查看全图；再按目标印刷宽度渲染。无需创建模拟XML内容的测试，直接验证可见效果和文件可用性。

核对以下项目：

1. **内容**：模块、图片和标签对应指定正文；没有新加的技术路线、未经证实数值或无关文献。
2. **拓扑**：每条连接的来源、目标和方向明确；层级、并行、反馈、对照和序列没有混用。
3. **排版**：同级基线、图片比例、标题间距一致；有足够内边距，没有图片标签或连线重叠。
4. **文字**：完整显示中文，在目标尺寸读得清；若拥挤则改结构或缩短标签，不无限缩小字号。
5. **视觉**：白底、少色、线宽分级统一；图标有具体意义，黑白查看仍能理解。
6. **素材**：配对变化显著，未改变非目标因素；动作接触与支撑可信。
7. **文件**：内嵌图片全部可解码；在无素材目录依赖的情况下正常打开；PPTX 中保留 SVG，渲染与原图一致，编辑能力的描述与实际核验结果一致。

逐项复核用户锁定的标签、指标与复刻局部，检查解释句是否可以删除、每个形状能否辨识其研究对象、颜色是否含义一致。检查所有箭头起终点、分支合并含义及反馈通道，不能仅检查是否有重叠。用最终渲染图判断视觉质量，不用XML合法、形状数量或颜色数量代替验收。

发现问题后修订并重新渲染，不能把旧预览当成新文件的验证结果。优先修复整体对齐和路径，再处理单个图标。

## 插入Word或PPT

默认生成独立 PPTX 可编辑副本，流程见上文；插入用户已有 Word 或 PPT 仅在用户要求时执行。使用对应文档或演示技能读取目标版式，不随意重排整篇文档。Word支持SVG时嵌入SVG，必要时同时提供兼容PNG回退；检查矢量源实际保存在文档资源中。

用户要求Word原生可编辑形状时，按 [技术附录](word-native-shapes.md) 将路径、边框、箭头转成原生形状，文字转成可修改的文本框。嵌入整幅SVG、PNG或文字轮廓均不能替代这一要求。优先将形状组成单个组合图，核对字体与坐标比例；在Word中实际打开并渲染，检查图题与图同页、正文不被浮动图遮盖。只有确实保留原生文本才能称文字可编辑。

文件占用时不关闭用户文档或强行覆盖；另存清晰的新文件名并告知。维护图形源与交付副本的对应关系，旧版本通过Git或明确备份保留，避免新SVG与旧PPT混称同一版。

插图放在研究小节的引言或指定位置，图题与图片保持同页。新增编号承接目标文档的图号，不能照搬参考图编号。只添加必要的图引用，不为插图大幅改写已确认正文。用户要求另存时保留原稿。

使用目标文档渲染流程检查插图、图题、相邻正文和分页。只确认文档能够打开不代表排版检查通过。

## 交付

简要说明改动，提供最终 SVG 和同名 PPTX 可编辑副本，必要时说明尚未核验的逐元素编辑能力；有素材时提供素材目录与提示词位置。生成照片标明是方案示意，不称为真实实验结果。PPTX 仅承载示意图，不扩大交付为汇报演示文稿、网页或整篇项目书。

## 当前文件与导出的一致性

用户手改PPT是新基线，不得用旧SVG或生成脚本覆盖。已有原生形状保持原生编辑，SVG从最新PPT导出；新图SVG导入PPT只保证整体编辑。移动模块同时检查组外连接符、锚点、图层和标题端点。

主标题、内部强调与辅助文字按所选模板验收。SVG显式白底，避免透明区域在深色查看器变黑。使用PPT主题色时解析实际色值，不能按tx2默认黑色导出。

失败中间文件仅留临时目录，最终文件夹只放通过实际Office打开和渲染的交付版。重试前检查已有输出及文件占用，不关闭用户文档。格式规范化不保证保真，必须复核正文、修订记录、公式与其他图片。字体、照片或文字缺失时修复并重新渲染，不能只报告结构校验通过。
