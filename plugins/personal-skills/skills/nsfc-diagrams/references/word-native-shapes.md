# Word原生形状技术附录

仅在用户要求Word可编辑形状时读取。配合documents技能执行，不在图面出现这些实现细节。

## 转换

- 优先复用已经验证的转换器。转换前检查SVG元素和变换类型；不支持的路径不得静默丢弃，应扩展支持或明确阻塞。
- 将矩形、圆、路径、箭头变成Word DrawingML原生形状；照片仍作图像。文字独立保留为原生文本框，禁止用轮廓替代文字编辑能力。
- 统一使用实际EMU坐标。1厘米=360000 EMU，1磅=12700 EMU。由目标图宽/viewBox宽度得到缩放比例，组的ext与chExt采用对应实际尺寸，避免组缩放与字体缩放叠加。
- 字号按印刷尺寸转换；需要整数半磅时检查舍入后的文字宽度。根据字体测量设置文本框宽高、基线与内边距，不仅依赖SVG基线属性。
- 已验证的Word文本框配置采用`wrap="square"`、固定尺寸和`a:noAutofit`；`wrap="none"`曾导致Word自动收缩图框。仍须逐次实际渲染，不把配置视为显示正确的保证。
- OOXML颜色转为六位十六进制，如`white`转为`FFFFFF`。自定义路径、形状ID及命名空间必须有效。

## 插入和排版

- 定位指定章节与图号，检查旧图是否为浮动图、是否将图题放在组合内部。移除旧图时同时处理其AlternateContent/VML兼容分支，避免重复显示，保留宿主段落正文。
- 默认按版心放置约15厘米宽组合图，独立段落居中；图题独立排版，与图保持同页。若目标样式有明确浮动布局，按其要求处理并检查锚点。
- 仅修改任务涉及的图和必要段落排版。保留其他正文、公式、图像及资源，另存时不覆盖原件。

## 核验

1. 确认目标图含原生形状和文本框，不是整图图片；逐项核对标签、路径与箭头。
2. 在Word实际打开、重新分页、导出并按documents技能渲染。检查全图和实际尺寸，重点检查插图页、图题及相邻页；按该技能要求检查其余页面。
3. 核对未涉及内容及源文件未被改动。包级比对与形状计数只作结构证据，不能代替视觉检查。
4. 报告真实编辑能力；未实测的取消组合操作或逐元素编辑行为不作保证。字体、坐标或文字发生畸变时修正后重新渲染。

## PPT原生对象转换补充

- 以用户最新PPT为来源，沿组层级合成off/ext/chOff/chExt坐标变换。组外连接符须单独定位。保留旋转、翻转、路径与渐变；不支持的对象先扩展转换或说明限制。
- 显式注册DrawingML的a及图片pic命名空间；复制图片时不要将a:blip、a:xfrm等子节点错误改为pic命名空间。检查嵌入关系、媒体路径和Content Types，单独检查全部场景图片是否显示。
- 解析主题、母版映射和明暗修饰，输出明确RGB。tx2在已核对参考中是#0E2841，不能一律回退黑色。记录字体继承并采用当前模板字体，不固定所有Word图为宋体。
- 文本转换时保留字重、颜色和段落对齐。字号按实际尺寸换算；精确行距可避免文本框内基线截断，但需依据字号与字体测量校准，不盲用全局固定值。小字号半磅舍入后检查长标签。
- 包规范化曾解决个别来源文档兼容问题，但不是通用修复保证。用python-docx等工具另存后必须比较正文、修订记录、原有公式和图片，不能因能打开就声称无变化。
- 原生形状和文本框计数只是结构证据；必须实际Office打开、分页、导出，并按documents技能检查真实显示。单个项目脚本不能未经整理直接推广为通用转换器。
