# 机制图正反例

示例说明选择原则，不要求其他研究图沿用本轮图4的模块、机器人或雷达。

|需求|易误解的表达|更合适的表达|
|---|---|---|
|三套训练策略和超参数配置|三组不具名蓝绿色块，标“案例配比”|三份折角配置文件，配简短“训练策略 · 超参数”标签|
|按给定参考复刻候选筛选|改成没有候选名称的方块增长链|保留入口、候选一/二/三、停止分支和继续训练分支|
|显示工具集合|大框无标题，仅靠读六个标签猜含义|外框标“工具库”，各工具图标表达具体操作|
|表达工具交互|孤立的“调用”“返回”|箭头旁标“工具调用”“结果返回”，为四字标签调整间距|
|接纳或恢复更新|仅写文字或仅用红绿|矢量√接纳、×恢复，沿明确的分支进入反馈回路|
|用户指定预测准确度、物理一致性等指标|自行替换为近义但不同的指标|逐项保留用户指标及“推理开销”等限定词|
|布局显得单薄|补长说明、大标题条或无关图标|放大有研究含义的机制元素，重新分配留白|
|复杂工具调用与反馈|直接相交，再到处加跨线桥|先预留外缘反馈和独立调用通道，调整接口消除交叉|

复杂新图的局部预览应覆盖最难辨识的机制，例如候选配置究竟是文件、数据集还是网络。给出实际局部草图和它在整体中的位置，讨论对象与关系是否正确；已确认的局部不再重新抽象。用户只要求局部修订时，保持其余已确认内容。

颜色丰富不等于大面积彩色背景。可用文件折角区分类别，用模型节点突出更新位置，用灰色终止路径和红叉表示停止；所有颜色变化都应能解释。图面删掉说明后若机制不可懂，应先修正形状表达，再添加必要短标签。

## 总体框架图及语义保真补充

| 问题 | 避免 | 正确处理 |
|---|---|---|
| 能力边界 | 随手画阶梯线 | 先确认分区语义，边界贴合对应色块交界 |
| 多个交互片段 | 一模一样的卡片 | 用不同状态或轨迹表达确有差异的片段，不虚构实测 |
| 视觉/语义记忆 | 泛化文件堆代替全部记忆 | 视觉帧叠片与语义token分别分层；跨案例存储另行表达 |
| 专家状态 | 只调整颜色但编号/连线不变 | 核对位置、编号、实虚线及各路输出状态一致 |
| 编号标题栏 | 只移动背景 | 编号、斜切、底色和文字整体跨接模块上边框，调整箭头端点 |
| 手动PPT修改 | 旧脚本重生成覆盖 | 使用当前PPT为基线，保留非目标对象 |
| 主题色 | tx2当黑色 | 解析主题与映射，例如已核对参考为#0E2841 |

以上是语义核对示例，不要求其他研究图必须出现记忆、专家、机器人或能力分区。
