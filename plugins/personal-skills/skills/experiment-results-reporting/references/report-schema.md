# 报告字段与 Excel 格式规范

## 固定工作表与列宽

默认生成前两张表，有 baseline 比较需求时增加第三张。表头位于第 1 行，正文从第 2 行开始。下列宽度为 Excel 列宽单位，不是像素；行高单位为磅。各列按下表顺序生成，不能依赖旧 Excel 获取样式。

| 工作表 | 列名与宽度（从左至右） |
|---|---|
| 表1 验证集组成与设置 | 数据集 14；任务 ID 38；rollout 数 12；seed 17.3；任务目标 68 |
| 表2 实验结果汇总 | 数据集 14；任务 ID 27；有效任务数 13；成功数 10；失败数 10；成功率 13；总 token 20；平均 rollout 时间（秒）21；平均仿真时间（秒）19；平均扣除仿真时间（秒）23；API 等价费用（USD）20 |
| 表3 baseline与ours对比 | 数据集 14；任务 ID 27；方法 27；有效任务数 13；成功数 10；失败数 10；成功率 13；总 token 20；平均 token 20；平均 rollout 时间（秒）22；平均仿真时间（秒）20；平均扣除仿真时间（秒）23；API 等价费用（USD）22 |

任务目标来自实际 manifest 或 benchmark API，不根据任务名臆测。数据集顺序沿用评测清单，任务顺序沿用各数据集 manifest；比较表两种方法按同一任务键对齐。原始任务 ID 原样保留，不再次拼接数据集前缀，不增加冗余 suite 列。

所有数据集默认展开到任务级；一个任务有多个 seed 或 rollout 时，结果按任务汇总，表1保留其 rollout 数及完整 seed 列表，不能把一次 rollout 冒称整个任务。只有 suite 汇总证据时，不伪造任务明细，明确说明限制。

## 固定样式参数

| 项目 | 参数 |
|---|---|
| 字体 | 所有表格单元格宋体，11 磅，黑色 `#000000` |
| 字重 | 表头、数据集合计、Overall 加粗；其他正文不加粗 |
| 对齐 | 水平 `center`、垂直 `center`，包括数字、文本、缺失标记和合并区域 |
| 底色 | 白色，无彩色表头、无斑马纹；隐藏工作表网格线 |
| 表头行高 | 44 磅，自动换行 |
| 表1正文行高 | 47 磅 |
| 表2、表3正文行高 | 28 磅，合计行相同 |
| 换行 | 表头和正文文本启用自动换行；数字不拆行；不启用缩小字体填充 |
| 溢出处理 | 默认列宽固定；文本截断时仅将对应行高以 14 磅为增量增加至完整显示，不缩小字号。合并区域需单独检查显示效果 |
| 表格顶线 | 表头整行上边框，黑色 `medium` |
| 表头下横线 | 表头整行下边框，黑色 `thin` |
| 数据集分隔线 | 每个数据集最后一行下边框，黑色 `thin`，覆盖全部表格列 |
| 表格底线 | 表格最后一行下边框，黑色 `medium`；与分隔线重合时使用 `medium` |
| 其他边框 | 无竖线、无外框左右边线、无逐行网格；不在每对 baseline/ours 中间加线 |

不把 `medium`/`thin` 随意换成不同软件的像素值；使用生成库对应的 Excel 原生边框样式。边线必须覆盖合并区域所在列，不能只给有文字的单元格画线。

## 数字格式

| 字段 | Excel 格式 | 示例 |
|---|---|---|
| rollout 数、有效任务数、成功数、失败数、总 token | `#,##0` | 1,234 |
| seed | `0`；多个 seed 时使用文本列表 | 0 或 0, 1 |
| 平均 token | `#,##0.00` | 1,234.50 |
| 成功率 | `0.0%`，底层存 0–1 比例 | 62.5% |
| 所有时间 | `#,##0.00`，表头标明秒 | 1,234.50 |
| API 等价费用 | `#,##0.00`，表头标明 USD，不添加货币符号 | 12.34 |
| 缺失 | 文本值：单个反斜杠 `\` | `\` |

数值保存为数值类型，不能把千位分隔符和单位拼入字符串；底层保留原始精度，只通过格式限制显示小数位。零必须显示为 0、0.00 或 0.0%，不能用缺失标记替代。两张结果表对同类指标使用一致格式。

## 合并与汇总

- 数据集独立一列。表1合并该数据集全部明细行；表2、表3合并该数据集明细与其合计行，不跨数据集合并。
- 表2每个数据集明细之后增加一行“合计”，表末增加一行 Overall。Overall 行 A 列写 Overall、B 列写合计。
- 表3每个任务固定两行：baseline、ours；任务 ID 在 B 列跨两行合并，C 列保留两个方法名。每个数据集末尾有 baseline、ours 两行合计，B 列合并显示“合计”；分隔线画在第二行合计下方。
- 表3末尾 Overall 也分 baseline、ours 两行，A 列合并显示 Overall，B 列合并显示合计；整张表的底线画在第二行下方。
- 合计的任务数、成功数、失败数、token 和费用从原始条目聚合；成功率重新用成功数/有效任务数计算。各时间及平均 token 按对应有效记录计算，不能简单平均各行均值。
- 表内“有效任务数”对应结果可判定的 rollout 条数；同一任务多个 rollout 时计入各次有效结果。聊天中说明实际分母以及未知、未运行、token/timing 缺失条数。
- 无可判定结果时成功率显示 `\`；未知和未运行保留对应任务行，不能为表格完整而填成失败。

## 说明与交付

不默认增加表下注释、说明页或附属说明文件。以下必要信息在聊天中简短说明，字段详细定义仍按本 skill 的统计规则执行：

- 数据来源、任务覆盖范围、未知/未运行、重试是否计入，token/timing 各自的有效分母与缺失数量。
- 影响复现的运行设置：模型/effort、响应预算、timeout、环境步数、策略、memory、代码版本和硬件；已知设置不能冒称官方默认值。
- 计时区间差异、费用计价版本及估算/覆盖限制；字段缺失不能以不等价指标替换后仍用原列名。

交付只简短说明结果和重要限制，并用纯文本或代码块提供 `.xlsx` 绝对路径；不使用 Markdown 文件链接，不重复整份表格。

## 呈现验收

交付前重新打开生成文件，检查三类内容：

1. 核对字体、行高、列宽、数字格式、合并范围与边框；合并后的数据集列仍有完整分隔线和底线。
2. 核对原始任务 ID、baseline/ours 配对、数据集合计、Overall，以及缺失与真实零值；更改统计粒度时重新计算，不能仅替换标签。
3. 预览表头、长任务目标、合并区域和合计行，确认没有截断、重叠或数字溢出。修改已有报告时，只变更用户指定内容，保留无关手工调整；新建报告不需历史模板。

## 结果分类

- success：环境 finalizer/solved 状态明确成功。
- failure：任务未完成，包括 harness 决策/步数预算耗尽及规划、代码、控制失败；保留有效用量。
- infrastructure_interrupted：服务或网络故障使任务无法继续，尚无可判定结果。
- unknown：核对工具、预算和原始轨迹后仍无法判断任务结果，写明缺少的证据；缺少 finalizer 本身不构成未知。
- not-run：因续跑、预算或调度未执行。

未知和未运行不能计入成功率分子或分母；除非另有定义，不把失败从成功率分母排除。

## Token 与费用

按 SKILL.md 的归因规则选择有效请求，使用其最新去重累计 usage。任务结果和用量来源分开记录：

- input_tokens
- cached_input_tokens
- output_tokens
- reasoning_output_tokens（若有；不再次加入 output）
- total_tokens = input_tokens + output_tokens
- included_attempt_ids / included_response_ids：纳入的尝试或响应；保留在统计中间数据中；默认不另交付映射文件
- excluded_requests：请求/尝试 ID、服务失败原因、日志来源和已知被排除用量
- termination_cause / evidence：任务结束原因及预算、工具或 finalizer 证据
- usage_source / coverage：累计记录来源、覆盖哪些有效响应
- missing_valid_usage：确实缺失的有效响应 ID、字段、原因；没有则为空
- token_n / timing_n：各指标的任务分母及其选择原因

不用 `complete | partial` 标记代替因果判断。累计值覆盖全部已选有效响应时即可统计，不要求一定存在终结 usage 事件。

## 归因示例

| 原始证据 | 结果与用量处理 |
|---|---|
| 前两次连接/容量失败无 usage，第三次完整尝试成功且有 usage | 任务成功；第三次尝试全部有效 usage 纳入总量与均值，前两次排除；有效任务数为 1 |
| 有效交互后用完 40 次工具决策，finish(failure)，随后外层 timeout | 任务失败且计入分母；恢复全部有效响应的累计 usage，不因外层 timeout 或缺少 turn.completed 剔除 |
| API 重连到上限，未产生有效响应 | 服务失败，单列基础设施中断；没有 usage 不填零，不归为能力失败 |
| 模型给出错误代码、反复调整但最终预算耗尽 | 有效模型响应仍计入用量与费用，任务失败计入分母 |
| 只有累计记录但不能确认是否覆盖某个有效响应 | 指明该响应及缺失证据，保留已记录用量与任务结果；不凭猜测补齐，也不用 partial 自动剔除整条 |

替换已授权补跑的服务中断 episode 时，新旧来源分别记录；同一 episode 不重复计数。任务内有效多轮响应应累计，不能只保留最后一次响应。

费用计算前记录官方价格页 URL、读取日期和模型版本，并在聊天中交代计价依据。长上下文加价必须按请求逐条判断，不能只按平均输入长度判断。

## 外推

设 suite 为 s，目标全集条数为 N_s，有效样本平均 token 为 mean_tokens_s，则：

estimated_total_tokens = Σ_s N_s × mean_tokens_s

费用同理。若某 suite 没有有效样本，整体估算应为 null（Excel 显示 `\`）或明确列出未覆盖 suite；禁止用零填充。仅在用户要求时增加“完整全集外推”行；该行成功率及真实任务结果显示 `\`，在聊天中说明未评测及外推假设。

## 复现清单

汇总前检查：

1. 输出目录和 run manifest 是否对应同一 run。
2. 清单哈希、代码版本、模型、policy、memory 是否记录。
3. 任务数是否等于预期，task ID 和 seed 是否唯一。
4. 每条结果是否能区分成功、失败、未知、未运行。
5. token/timing 的有效样本数是否分别计算。
6. 服务请求重试与任务决策预算是否区分；每次排除是否有原因、ID 和证据；能力失败的有效用量是否保留。
7. 外推目标（例如 8 suites × 10 tasks × 10 seeds）是否明确。
