# 失败轨迹分析

从实际执行证据建立因果链，回答用户指定的问题，例如“何时开始绕路、谁在控制、为什么没有纠正”。不要用最终掉落、超时或任务失败替代对更早偏离事件的分析。分析请求本身不授权修改执行代码、提示词、策略、依赖或重跑任务。

## 确定案例与证据

- 确认 task、seed、run、planner 后端、模型及环境版本。多个同名运行时先通过场景、截图、参数和时间匹配；无法匹配就说明，不拼接不同运行的证据。
- 先枚举文件、定位单个 episode，再解析内容。避免递归搜索整个日志、缓存和资产目录；原始 JSONL 可能包含大段 base64 图片，解析后只输出所需字段。
- 优先检查原始 session/事件流、完整工具参数及返回、模型输出、状态记录、视频、运行日志。人工摘要、最终 audit 和 agent 自己的成功声明是待验证的陈述。
- 核对执行时的代码和配置。当前工作树可能与运行版本不同；优先使用运行清单、提交号、部署快照和 session 中的实际工具定义、提示词。只能查到当前代码时标明限制。
- RPent 常见入口：episode 内的 `states.json`、`episode.mp4`、`transcript_*.json`、`*.stream.jsonl`、`run.log`、`vla_server.log`。不要假定 `transcript` 包含全部原始内容；先检查其 schema 和后端。

## 还原 agent 当时真正获得的信息

在解释 agent 为什么决策之前，检查相关决策点的 session：

1. 找到调用 ID、参数、开始/完成事件及返回。确认每个图像块来自哪个工具、哪个状态步骤、哪个相机、何种分辨率；从原始返回解码图片，必要时通过哈希或像素比较核对磁盘产物。
2. 分别列出“该次新增输入”“此前上下文已有信息”“只存在于分析者的视频/仿真状态中的信息”。杯子曾出现不代表当前图像可见；保存了视频不代表模型收到过视频；工具端生成了图片也不自动证明模型请求最终包含图片。存在桥接过滤、压缩、裁剪或 `no_images` 时继续追查。
3. 将 agent 的实际输入图片按决策点做带标签的对照图。与视频关键帧分开标注，不能用任意视频帧冒充当时模型输入。引用图片及 session 事件行号或 ID。
4. 读取已保存的可见推理摘要、公开说明、工具选择及下一次调用。空的 `reasoning.content` / `summary` 不是可读推理；加密内容不作解释。公开 commentary 只能证明模型表达了什么，不等同完整内部推理。
5. 核对输入中的数值、接触/持物信号、目标位置和提示词限制，不能只读 RGB 或模型解释。区分“模型没有得到证据”“得到了但没有提及”“明确识别异常却继续执行”。图像中物体靠近夹爪不等于接触成立或稳定抓持。

## 对齐视频、动作与决策时间线

至少区分以下时间轴，不互相代替：

| 时间轴 | 可支持的结论 |
| --- | --- |
| 视频帧号与播放时间 | 图像中的运动次序；注明帧号从 0 还是 1 开始 |
| 仿真控制步与 action chunk | 哪次预测生成了被执行的动作、何时刷新观测 |
| 实际日志时间与调用耗时 | 工具占用时间、agent 的决策机会与等待间隔 |
| 纯模型预测耗时 | 只有预测级计时存在时才能量化 |

- 读取视频 FPS/时间戳和录像代码，确认录的是每个控制步、抽帧还是实时录像，是否含初始帧、重复帧及等待时间。变帧率视频用实际时间戳。
- 依据真实 `steps_applied`、帧计数和工具边界建立对应关系，用边界状态图验证偏移。只有确认每步一帧且无额外帧时，才可累计步数推导调用的帧区间。
- 先用低密度关键帧找到目标事件区间，再逐块、逐帧缩小区间。用户问开始绕路时，围绕开始偏离及继续偏离提取，不把主要精力转移到后续掉落。
- 追查策略循环：预测 horizon、每次实际执行步数、每工具调用的 chunk 上限、历史更新和提前退出条件。区分“生成长度”“执行长度”“上层观察间隔”；参数以运行时有效值为准，不只看默认值。
- 核实谁有控制权、谁在等待、是否存在并行观测或中断通道。VLA 执行中不等于 agent 能看到中间状态；异步线程存在不等于具备语义异常监控。agent 思考期间仿真是否继续推进也应检查。
- 工具耗时可能含预测、RPC、仿真、渲染、序列化；不得将其称为纯推理时间。没有每块时间戳时，不按均匀耗时把视频帧强行映射到精确墙钟时刻。

## 定位偏离，而非追认“错误第一帧”

先给偏离一个可检验的定义：例如越过目标接近区域后持续离开、反复返回已完成的阶段、执行了不符合当前子目标的动作。结合任务定义、目标定位、可通行区域和障碍检查；必要的退出、转身、避障不能仅因瞬时距离变大就判错。

- 区分“开始移动”“首次出现偏离迹象”“已有充分证据判定异常”“agent 首次能够获知异常”。它们可能是不同帧或不同调用。
- 若只有终点状态，没有逐帧坐标或正确参考路径，就报告视觉证据的帧区间、判据与不确定性。不能伪造唯一正确路径或精确到帧的因果结论。
- 端点位移不是累计路程；相机旋转不是底盘平移；画面左侧不是固定世界方向。“绕半圈/一圈”需要连续视角、地标或轨迹支持，不能顺着用户的描述直接认定。
- 视频可证明动作怎样发生，不能单凭画面确定 VLA 为何选择该动作。若只有预测输出而没有策略内部诊断，归因应止于可观察的策略行为。

## 按决策机会建立因果链

对每段关键行为回答：

| 字段 | 内容 |
| --- | --- |
| 帧区间 / 视频时间 | 首次迹象、明显偏离、调用返回等具体位置 |
| 调用 / chunk / 实际耗时 | 标明实测、推导或未知 |
| 控制者与动作 | agent 下发了什么；VLA、导航器或执行器实际做了什么 |
| agent 此时收到的证据 | 具体图片、状态字段、历史和有效指令 |
| 实际判断与后续动作 | 引用已保存文本和调用，说明是否存在干预机会 |
| 证据定位与限制 | 文件、事件 ID/行号、图像及缺失记录 |

沿时间顺序分别检查：

- **信息缺失**：关键变化未送达、视角遮挡、缺少过程帧或上下文丢失。不要仅因模型判断错就推断它没看见。
- **决策/监督问题**：目标分配错误、过长的无检查执行窗口、明确异常后仍续跑、错误恢复。引用实际决策，不用事后理想方案替代证据。
- **VLA/导航策略问题**：给定正确任务和可用观测后持续输出偏离动作；区分一次旧动作块执行和多次新观测后仍持续偏离。
- **执行/感知接口问题**：动作映射、坐标系、陈旧观测、夹爪控制、碰撞或仿真异常。仅在具体证据支持时归入，不罗列成无依据的可能原因清单。
- **提示词/运行协议约束**：实际有效的续跑规则、chunk 覆盖、禁止子任务等是否约束了 agent。区分遵循了不合理约束与违背合理指令。

可能是多层原因叠加。将结果表述为已证实事实、证据支持的解释和待验证假设；有证据足够明确时直接下结论，不用泛泛的不确定性掩盖事实。没有中间反馈与收到反馈后仍不纠偏，应分别归因。

## 交付与停止条件

先直接回答用户关注的时间段、控制者与原因，再提供关键时间线、agent 实际输入对照图、必要的视频连续帧和证据链接。分析产物放到独立目录，保留原始 session、视频和评测结果；不要未经请求将诊断写入长期 memory 或改写原始失败结论。

结论应说明最早有依据的异常、下一个可干预点、实际采取的动作，以及为何仍继续。缺少数据时明确还缺哪项证据、它限制了哪个结论；不能靠不断抽取无关帧补足未保存的数据。

如需验证因果，只提出与假设对应的最小对照，例如固定同一决策点，对比终点图片与新增过程帧；或固定初态、策略及其他参数，仅改变监督间隔。单次重跑成功不能证明原始根因。除非用户已授权，不启动付费模型调用、仿真重跑或机器人实验。
