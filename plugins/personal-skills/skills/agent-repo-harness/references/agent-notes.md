# Agent Notes

Agent Note 相当于由 agent 撰写的 RFC / ADR：记录代码、测试和现有文档无法承载的“为什么”和“放弃了什么”。下面是 DSH 的机制，按目标仓库规模取舍；写入目标仓库时用目标仓库的语言表述。

## 位置与命名

默认放在 `.agents/notes/`（目标仓库已有 ADR 目录时可沿用）。路径同时编码生命周期和分类：

```text
.agents/notes/{lifecycle}/{class}/YYYY-MM-DD-topic-title.md
```

- **lifecycle**：`proposed/`（待评审、未实施）、`implemented/`（已上线）、`rejected/`（已否决），以及独立的 `archived/`。状态变化即移动文件。
- **class**：封闭集合，例如 `feature`、`bug-fix`、`simplification`、`architecture`、`process`、`testing`。小仓库可以减少分类甚至不分类；新增分类要同时更新规则文件和检查脚本中的集合。
- 日期是首次提出的日期。note 之间用相对 Markdown 链接互相引用，便于机械检查。
- 不建集中的 `INDEX.md`：目录树就是索引，集中索引会重复路径信息并造成提交冲突。

## 何时写

只在有持久的决策理由、且代码 / 测试 / 现有文档无法解释时才写；与代码改动同一提交。已有 note 覆盖该决策时更新它，不建重复 note。机械性、局部修改（包括局部 UI 调整）不写。

## 文件格式

前三行固定，便于脚本检查：

```markdown
# Agent Note: <标题>

Status: proposed | implemented | rejected — <一行理由>
```

`Status:` 必须与所在目录一致，不带日期或括注。正文以“问题”节开头，之后按生命周期要求不同的节：

| lifecycle | 必需节 | 说明 |
| --- | --- | --- |
| `proposed` | 问题、方案、备选方案、验收标准、风险 | 方案可以用将来时 |
| `implemented` | 问题、决策、备选方案、影响 | 用现在时描述已上线的现实；禁止出现方案 / 计划 / 迁移计划 / 验收标准等提案期节 |
| `rejected` | 问题、方案、备选方案 | 冻结的提案，结论写在 Status 行 |

**备选方案节是强制的**：每个真实的备选及其落选原因。只记录真实考虑过的备选，不虚构。节名使用目标仓库语言，但必须在规则文件和检查脚本中保持一致。

## 生命周期规则

- **proposed → implemented**：更新 Status 行，把“方案”改写为现在时的“决策”，把验收标准和风险并入“影响”或现在时的“测试”节，删除计划。
- **implemented 保持与现实一致**：代码移动文件、重命名、改默认值时，在同一改动中更新 note 中的事实（路径、名称、结构），直接改写，不追加变更历史。
- **不改写决策本身**：推翻决策或理由时新建 note 并互相链接。
- **取代检查**：每新建一个 note，搜索覆盖同一决策或机制的旧 note。完全取代的旧 note 可以在保留其所有独特理由、备选和后果到新 note 后删除，并修复入站链接；部分取代则两者都保留并互相链接。
- **删除**：只描述机械或小型 UI 调整的 implemented note 可以删除；被否决的 note 只在能防止一个可信的错误时保留。

## 归档与冻结

- 只有 implemented note 能归档：决策已完整上线、理由不太可能指导未来工作、但仍有历史价值时，移动到 `archived/{class}/`，并在 Status 行下插入 `Archived: YYYY-MM-DD`。这是归档时唯一允许的内容修改。
- 仍有用的备选方案、所有权边界、否定性保证、持久化或协议语义、安全规则、重新引入条件时，保持活跃，不归档。
- 归档后永久冻结：不编辑、不重排、不翻译、不移动，也不作为当前行为的依据。文档检查跳过归档文件（包括其外链）；活跃文档仍可链接到归档 note 作为历史引用。
- 不以字数、年龄或配额决定归档。

## 写入目标仓库的文件

- `.agents/notes/README.md`：上述布局、分类表、何时写、格式、生命周期与归档规则。
- `.agents/notes/AGENTS.md`：每新建 note 触发取代检查；`archived/` 冻结。
- `.agents/notes/implemented/AGENTS.md`：保持事实与现实一致，但不改写决策。
- `.agents/notes/archived/AGENTS.md`：冻结规则与唯一允许的归档修改。
- 根 `AGENTS.md`：一行创建条件和一行冻结规则，链接到 README。

如果目标仓库没有任何值得记录的历史决策，只建规则文件和空的生命周期目录（可用 `.gitkeep`），不要为了示范编造 note。
