# build-harness 规格

## 目标

新建 skill `build-harness`，指导 agent 参照 DeepSeek Harness（DSH）的做法，把一个目标仓库整理成便于 agent 工作的仓库：分层 `AGENTS.md`、描述当前事实的 `docs/`、记录决策依据的 Agent Notes，以及可选的可执行检查脚本和 CI 接入。

## 已澄清的需求

1. **职责划分**：skill 负责一次性的调查、设计和搭建；后续日常维护所需的规则必须写进目标仓库自身（根 / 子树 `AGENTS.md`、`docs/AGENTS.md`、notes 规则、检查命令），不依赖再次调用 skill。skill 不设“增量维护模式”。
2. **覆盖范围**：skill 必须同时包含文档体系、检查脚本、CI 三部分的说明与指导。
3. **自动化程度由用户选择**：agent 在调查后向用户说明收益与改动，并提供三档选择：仅文档体系；文档体系 + 本地检查脚本；文档体系 + 检查脚本 + CI。
4. **检查脚本是可运行代码**：检查相对链接（按 Markdown 语法识别真正的链接标签、转义、尖括号目标、成对括号与围栏）、notes 状态与目录一致性及必要结构（根目录只放规则文件，占位文件忽略）、文档长度预算（提供 `--init` 生成清单，未启用时无需清单）、归档 notes 冻结；错误输出指明文件和原因，失败返回非零退出码。
5. **CI**：复用目标仓库已有平台与运行环境，调用与本地相同的命令。
6. **验证**：既验证正常文档通过，也在隔离的临时副本中用错误样例确认脚本能发现问题，不在目标工作树中改动再还原。
7. **不照搬 DSH 细节**：新建的 Agent Notes 中已实施记录随代码更新事实、只有归档记录冻结；预算只覆盖清单中的文件；规模按目标仓库裁剪，目录按需创建。
8. **skill 自包含**：使用者只拿 skill 就能整理仓库，不需要了解 DSH；skill 中不出现来源叙述或专有命令对照。
9. **沿用成熟既有约定**：已有成熟 ADR（如平铺、带索引的 `docs/adr`）时沿用其索引、状态、归档、格式与可变性规则，不强行迁移，也不套用冲突的检查。
10. **保持所选范围**：用户选定的范围与自动化档位在整个流程中保持，并写入交付报告。

## 结构

- `SKILL.md`：目的、边界、主流程、询问节点、reference 路由。
- `references/layering.md`：分层规则与需写入目标仓库的维护规则。
- `references/agent-notes.md`：notes 生命周期、格式、取代与归档。
- `references/checks.md`：检查脚本设计、适配与验证。
- `references/ci.md`：CI 接入指导。
- `assets/check_agent_docs.py`：可复制到目标仓库并按需调整的 Python 标准库检查脚本。

## 放置

遵循本仓库规定：`plugins/personal-skills/skills/build-harness/`，并在 `README.md` 的 skill 表格与安装命令中登记。
